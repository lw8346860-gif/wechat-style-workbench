# 公众号操作台

面向微信公众号文章的语义结构导入、富文本排版、格式检查和复制工具。

- 桌面入口：`index.html`
- 移动入口：`mobile.html`
- 自定义主题仅保存在当前用户的浏览器本地存储中，不会上传到 GitHub。
- 指导范文在当前浏览器首次使用时显示；编辑或删除后会记住该状态，以后刷新保持空白编辑器。
- 基础识别在浏览器本地按明确规则区分作者、带序号且无句末标点的章节标题、不含任何标点的短标题与普通正文；摘要、导语等标签保守地按正文处理。
- 编辑区支持从 Word 全选复制图文后粘贴；图片原始字节单独保存在当前页面内存中，正文和撤回记录只包含图片编号，编辑时显示轻量预览。复制全文时才临时嵌入原图，原图不会因生成预览而被压缩或替换。
- Word 图片通过 HTML、剪贴板图片文件及浏览器提供的 RTF 图片数据接收；缺少图片数据时保留原位置的缺图占位，不猜测部分图片的对应关系。可单独复制图片补入，或点击“导入 Word”/拖入 `.docx`，在浏览器本地提取图文；旧版 `.doc` 请直接复制或另存 DOCX。
- 长文输入采用自适应闲时检查、延迟 HTML 输出和限额历史快照，减少大量文字进入编辑器时的输入卡顿。
- 工具栏“距”模块提供字间距、行间距和段间距各三档设置；默认使用中字距（0.1em）、中行距（1.8）和中段距（24px）。
- 章节标题字号支持 22/24/32；序号支持 `1.`、`一、`、两种换行样式、`01.`、`（一）`、`第一章` 和无序号。

GitHub Pages 使用 `.github/workflows/pages.yml` 自动发布。静态版支持排版、检查、Agent JSON 导入、剪贴板复制、本地主题和响应式移动端。

当前界面版本为 `v-1.0.6`。文章及原图不上传、不自动持久化，刷新页面会清空；主题继续仅存当前浏览器。格式清理依赖和 DOCX 解析器随 `vendor/` 静态分发，DOCX 解析器仅在导入文档时加载。部署时必须同时包含 `media-library.js` 和 `vendor/`。

复制测试已验证输出图片与导入原图字节一致，不等同于微信公众号接收验证；本轮尚未测试粘贴到微信草稿箱，也未实测所有 Word/系统/浏览器组合。

“直接读取公众号公开链接”采用端侧架构：GitHub Pages 只提供界面，用户电脑上的 `wechat-link-helper.mjs` 负责读取并净化公开文章。Mac 用户可通过 `启动公众号操作台.command` 启动。未运行端侧助手时，仍可粘贴带格式全文学习版式。

## 桌面端兼容性

- Windows 10/11：Chrome 或 Edge；如需读取公开链接，安装 Node.js 18+ 后双击 `启动公众号操作台-Windows.cmd`。
- macOS：Chrome 或 Safari；如需读取公开链接，安装 Node.js 18+ 后双击 `启动公众号操作台.command`。
- 无论系统，排版、JSON 导入、格式检查、富文本复制和本地主题都直接在浏览器内运行，不依赖 Node.js。
